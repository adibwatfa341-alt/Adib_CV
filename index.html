Enterprise Document Intelligence & Data Extraction

Turns scanned work-order PDFs of up to 72 pages into typed JSON inside the client’s ERP. I founded and built version 1; it grew into a 4-engineer platform in production for Saudi Electricity Company.

94%data-extraction accuracy
~70 sfor a 14-page, 52-field order
1 → 15work-order types I added (15 of 31)
0LLM calls to route 100% of pages
FastAPICeleryRedisGemini VLMOpenCVPyMuPDFDocker

The challenge

Each work-order package mixes SAP screens, letters, checklists, GIS maps and attachments. Entering one order by hand was estimated at 15+ minutes.

What I built

A spec-driven extraction catalog: each type has its fields, generated prompts, deterministic normalization and cross-field validation rules.

Architecture

FastAPI and Celery workers on Redis; PyMuPDF renders pages; OpenCV header templates classify every page and skip the 15 to 29 map and attachment pages; Gemini returns schema-constrained JSON.

Result

In production at 94% data-extraction accuracy, about 70 seconds per 14-page order.

Zero-Shot Tool Inspection & Anomaly Detection

I turned the AnomalyCLIP research model (ICLR 2024) into a FastAPI service in 3 days, then grew it into an inspection product: SAM 3 finds each tool, AnomalyCLIP scores its surface without defect examples, shape checks catch bent or broken tools, and a local Qwen3-VL judge gives each tool a verdict.

16 / 20defects found, 0 / 30 false alarms
~13xmore model coverage on a 20 px defect
1,950+judge stability runs (163 tools × 12)
3 daysfrom paper to first API
PyTorchAnomalyCLIPSAM 3Qwen3-VLFastAPICeleryReactTypeScript

The challenge

Field photos hold many tools at once, and there are almost no defect examples to train on. A small defect disappears when the whole frame is scored as one image.

What I built

SAM 3 segmentation that scores each part on its own (about 13x more coverage on a 20 px defect), robust calibration, outline-based shape checks, and a Qwen3-VL-8B judge with rules per tool type.

Architecture

FastAPI + Celery, a React/TypeScript UI in Arabic and English, a public /api/v1 with API keys for the Odoo team, deployed with Docker Compose on NVIDIA DGX Spark.

Result

16 of 20 defects found with 0 of 30 false alarms on MVTec hazelnuts. The judge was checked on a supervisor-labelled exam set and stability-tested over 1,950+ runs.

Case studyStatistics over defaults

Why the textbook threshold failed

The alarm threshold is learned from known-good parts: median + k · MAD. The textbook k = 3 looked safe but missed most defects. Move k and see what each choice does on 30 good and 20 defective parts.
